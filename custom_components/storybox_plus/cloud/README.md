# The cloud of the boxes

What this package knows about the manufacturer's cloud. The API is not
documented for third parties; the facts below were learned from the official
app and from the issues of the community project
[HA-Toniebox](https://github.com/git4sim/HA-Toniebox) (MIT). The code here is
written from scratch and imports nothing from Home Assistant.

## Sign-in (`auth.py`)

- Keycloak at `login.tonies.com`, realm `tonies`, client `meine-tonies`, Resource Owner Password flow.
- The access token lives **300 s**. The refresh token is rotated with every refresh; only it is stored. How long a refresh token survives unused is not documented; the login asks for `offline_access` first (a token that does not expire while unused) and falls back to a plain session if the client is not allowed offline tokens. `refresh_expires_in: 0` marks an offline token.
- Wrong credentials: 401 `invalid_grant`. Expired refresh token: 400 `invalid_grant`. Both end in `CloudAuthError`, which the integration turns into a reauthentication flow.
- Observed with a real account: the login returns an offline token (`refresh_expires_in: 0`, scope contains `offline_access`). **Every refresh returns a new refresh token; the previous one is accepted once more, then refused** (`invalid_grant`). So the newest token must be stored at once, and the stored token must never be used by anything but the integration: a second user of the same token breaks the integration's session.

## REST and GraphQL (`rest.py`)

- The OpenAPI description of the REST API is public: `https://api.tonie.cloud/v2/doc/?format=openapi` (Swagger UI at `/v2/doc/`). It documents 56 endpoints; the figure library (`myContentTonies`, `myDiscs`) is GraphQL and not in it.

- Base URL `https://api.prod.tcs.toys/v2`. `api.tonie.cloud/v2` is a CDN in front of it that lacks some endpoints (`/contenttonies`, `/discs`).
- `GET /me` → `uuid` (the user name of the push channel). `GET /households`, `GET /households/{id}/tonieboxes`, `GET /households/{id}/creativetonies`; some lists come wrapped (`results`, `households`, `creativetonies`).
- Boxes: tell the generation by the feature flag **`tngSettings`**, not by the field `generation` (`classic`, `rosered`, `tng`, `tb2g2`, …): the flag says what the box can do. `lastSeen` is camelCase. A classic box reports no figure and no battery; it is online while `lastSeen` is recent.
- Creative figures take `live` (the newest chapter plays first) in the same PATCH as `name` (also `private`, hidden from guest members, which the integration leaves alone); `chapters: []` clears them. A household is renamed with `PATCH /households/{id}` `{name}`. Its members: `GET /households/{id}/memberships` with `id, displayName` (always there: first name or email), `firstName, lastName, email` (as far as the account may see them), `profileImage` (an animal, `baer.svg` …), `mtype` (`owner`, `full`, `limited`), `isSelf, canEdit, canDelete`; the integration only reads them.
- Tunes (learned from the web app my.tonies.com): GraphQL `tunesItems(myTuneStatus: "owned")` lists the bought ones; per node `myTune { id assignCountRemaining assignedTonies { id tonieType householdId } suitableTonies { … } }`, `compatibleTonies { id }` and `allCreativeTonies` on the item. `suitableTonies` is "softly deprecated" and came back empty for a real account; what a Tune fits are its compatible figures and, with `allCreativeTonies`, every creative figure. `PUT /households/{id}/tonie/{figure}/tune/{myTune.id}` lays one on (figures of both kinds), `DELETE /households/{id}/tonie/{figure}/tune` takes it off; a creative figure's own chapters are kept meanwhile and play again afterwards. `contentTonies { tune { id item { title } } }` names the Tune on a bought figure too.
- Vouchers: `POST /tunes-vouchers/{code}` (empty body) answers with the Tunes it brought. Content tokens: `POST …/creativetonies/{id}/redeem-token` `{token}` adds ready-made content; the cloud converts the figure then.
- Push: `metrics/headphones` `{connected: [{type, battery, color}], speaker: {output}}`; an empty list means none.
- Public without a sign-in: `GET /version` (plain text, for example `v2026.11.10/602b7aff2`: the release, named after its date, and the commit; the commit changes with every deployment, so only the release is compared) and `GET /box-item-previews` (`bleColorId, displayName, thumbnail` per box colour).
- Locks: `PATCH /households/{id}/contenttonies/{tonie}` and `…/discs/{disc}` with `{lock}`; a locked one cannot be claimed into another household. Content figures also take `language` (multi-language figures only; the cloud names no list of their languages), discs `gameItem`.
- Notifications: `PATCH /notifications/{id}` `{read}` marks one read; `DELETE /system-notifications/{id}` dismisses a broadcast.
- Notifications: `GET /notifications` (`id, text, read, timestamp, ntype, tonieId, tonieReason`, also invitation fields) and `GET /system-notifications` (`id, translatedText`, broadcasts to all users). `ntype` values are not documented; the debug log names the shape of the first notification. Creative figures are renamed with `PATCH …/creativetonies/{id}` `{name}`, which converts nothing.
- Settings: `PATCH /households/{id}/tonieboxes/{box}` with the fields of the OpenAPI schema `Toniebox` (`name, maxVolume, maxHeadphoneVolume` documented as 25/50/75/100, which a classic box keeps to; a real Toniebox 2 reported 74 and 60; `lightringBrightness, bedtimeLightringBrightness, bedtimeMaxVolume, bedtimeMaxHeadphoneVolume, skippingEnabled, skippingDirection, scrubbingEnabled` with `tngSettings`; `ledLevel, tapDirection, accelerometerEnabled` without; `ageMode`, `language` behind their feature flags). `offlineMode` and `settingsApplied` are read only; `reset: true` resets all settings but name and language. `bedtimeLightringColor` is a string whose format is not documented. Whether a Toniebox 2 takes any percent when written is not checked yet (HA-Toniebox #67 claims 1 % steps).
- Bedtimes of a Toniebox 2 with the feature flag **`sleepTimerAlarm`**: `GET|POST /households/{id}/tonieboxes/{box}/bedtime-schedules`, `PATCH|DELETE …/bedtime-schedules/{schedule}` (not in the OpenAPI description; learned from HA-Toniebox #53). Fields `id, name, sleepTime, wakeupTime ("HH:MM"), days (monday … sunday), enabled, alarmEnabled, alarmTone, alarmVolume (0–100), alarmMorningLight`. The times are local to the box (`timezone` of the box); the days are those of the wake-up. A schedule alone makes the box ring once at most: the alarm has to be armed through `stl` every evening. **Not yet checked against the real account:** whether the list comes wrapped, and the shape of a created schedule (the debug log names the shape of the first one).
- `GET /playback-info/{toniebox_id}/{tonie_id}?contentVersion=<int>` tells the chapters of the figure on a box. `contentVersion` is **required**: the version of the content the box holds (0 while unknown). The answer has `status` (`available` with chapters, `outdated` when the version is behind, `unavailable`), `tonieType`, `title`, `series`, `tonieImageUrl`, `coverUrl`, `transcoding` and `chapters[{title, seconds, tuneTitle, coverUrl}]` **without ids**: a chapter is its position. The GraphQL library returns bought figures with an empty `chapters` list, so this is the only source of their chapters.
- `Toniebox.onlineState` is documented as `connected`/`offline`, but answers `unsupported` for the boxes seen; there is no "last seen" field in the API. `generation` is one of `classic`, `rosered`, `tng`, `tb2g2`, `pgs`; `product` e.g. `tbl`, `tb2`, `pgs`. `bleColorId` is an integer, `firmwareVersion` a string.
- **Chapters of bought figures** (learned from a HAR capture of my.tonies.com): the web app reads the library per household, `query { households { id contentTonies { id title lock imageUrl coverUrl languageUnicode series { name } chapters { name } secondsPresent } } }`, and the detail page `households(id: $householdId) { contentTonies(id: $contentTonieId) { … chapters { name } secondsPresent } }`. Those chapters have names only (no ids, no lengths); `secondsPresent` is the total length. The connection query `myContentTonies` answers `chapters: []` for the same figures. Lengths per chapter come from playback info (below), which also carries `contentVersion`-dependent data.
- The push message `playback/state` carries `contentVersion`; it is what `/playback-info` wants. With it the answer had `status`, `tonieType`, `title`, `tonieImageUrl`, `coverUrl`, `transcoding`, `nowMs` and 24 chapters with lengths for a figure of 24 chapters.
- Content figures and discs come from GraphQL (`POST /graphql`, fields `myContentTonies` and `myDiscs`, Relay pagination with `first`/`after` and `pageInfo`; without paging the lists stop at 100). Creative figures come from REST and carry `secondsRemaining`, `secondsPresent`, `chaptersRemaining`.
- Chapters of a creative figure are replaced with `PATCH /households/{id}/creativetonies/{id}` and a full `chapters` list; a chapter needs `file` (the file ID).
- Upload (not implemented yet): `POST /file` returns a file ID and a presigned S3 POST; the audio goes to S3 with the form fields before the file and without the bearer token.
- Figure pictures: use the URLs the API returns; fixed CDN URLs break (403). Box pictures: `GET /box-item-previews` per `bleColorId`.

## Push channel (`push.py`)

- MQTT 5 over WebSocket at `wss://ici.tonie.cloud:443/`, user name = the account's UUID, password = the access token. The broker drops the connection when the token expires and refuses the old token on reconnect (`Bad user name or password`): refresh before every connect, never log the refusal in a loop. Measured: the drop comes 299–300 s after connecting, so a session that ends within 15 s of its token's expiry is reopened at once with a fresh token; the gap is the refresh and the connect, about half a second.
- Topics `external/toniebox/{MAC}/…` with the MAC in upper case:
  - `metrics/battery` `{percent, raw, status}`; a box that shuts down sends only nulls.
  - `online-state` `{onlineState: "online"|"offline"}`.
  - `playback/state` `{tonie: "<id>", paused, chapter, chapterUntilMs, chapterDuration, chapterPositionMs, ended, downloading, blocked}`; sent again at every chapter change; an **empty payload** means the figure was taken off. While playing the position follows from `chapterUntilMs`, while paused from `chapterPositionMs`. Right after a figure is placed the box sends `downloading: true` together with `chapterUntilMs` and plays; the flag stays until the next message, which comes with the next chapter (seen 27 November 2026, firmware 1.6.28).
  - `volume/state` `{level (0..13), hardwarePercentage}`. The level is a share of the box's `maxVolume`: level 13 is the maximum, and the box rescales the level when the maximum changes (HA-Toniebox #67).
  - `app-reply/bedtime-state` `{stl: {state, duration, until, alarm}}`.
  - `settings-applied`: the box took the settings saved in the cloud (`settingsApplied` turns true); its payload is not read.
- Commands go to `external/toniebox/{MAC}/app-control/…`:
  - `playback` `{action: "start"|"pause"|"setPosition", chapter, ms}`.
  - `volume` `{level}`.
  - `stl` `{state: "on"|"off", duration}`; `duration` is a uint16 of seconds (at most 1092 minutes, more wraps around). The alarm settings live in the same payload (`oneTimeAlarm`, `alarm {morningLight, tone, volume}`), not in the REST API: the alarm rings when the timer ends. The app sends `alarm-preview` `{tone: null}` first; without it the box jumps to full playback volume (HA-Toniebox #53). The box answers on `app-reply/bedtime-state` with `alarm` set.
  - `sleep` `{}` after a short `stl` puts the box to sleep; it cannot be woken through the cloud.
- `aiomqtt` is used instead of paho's threads, which raced in the community project.
